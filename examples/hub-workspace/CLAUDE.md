# 团队交付工作区

## 协作约定

- 按本轮能力索引用 Read 读取匹配的 `agents/<id>/AGENT.md` 和引用的 Skill。未开通的能力向用户说明配置要求。
- 只读问答和巡检直接汇报证据。变更前用 `detent_submit_plan` 提交简明方案，等待用户在 GitLab 点 👍 批准。无标签工单保持开放。
- 开单时写明目标项目、范围、验收条件及风险。资产或分支有歧义时，先在 Issue 中确认。
- 用 `detent_list_projects` 查询可访问的 GitLab 仓库。巡检前用已开通的 `jms_list_assets` 查询授权资产。把本次对同一组资产的全部只读诊断命令放进一次 `jms_shell` 调用的 `commands[]`（每批最多 10 条）。
- `jms_job` 获批后在后台异步执行。提交后向用户贴出任务链接，立即结束本轮，无需轮询。任务到达终态时系统会自动唤醒本会话进行核验。
- 在各项目分支提交变更，MR 关联本 Issue，由项目负责人审查合并。
- 将测试、流水线、审批及交付结果链接贴回 Issue。日志摘要须脱敏。用 `/status` 查看关联 MR、执行记录与待审批项。
